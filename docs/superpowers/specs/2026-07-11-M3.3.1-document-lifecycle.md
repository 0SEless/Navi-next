# M3.3.1 — Document Lifecycle (Dirty Tracking)

## WHAT

Introduce a document lifecycle state machine into the existing WorkflowStore/WorkflowService layer. The system needs to know "has the document changed since last save" as a shared, observable truth — not as ad hoc comparisons scattered across features.

## Success Criteria

1. `WorkflowStore` exposes `saveState`: `'idle' | 'saving' | 'saved' | 'error'` — transitions owned by `WorkflowService`
2. `WorkflowService.save()` transitions `idle → saving → saved|error` and captures errors into `saveError`
3. `WorkflowSnapshot` includes the full lifecycle fields so UI can subscribe via existing `useSyncExternalStore` pattern
4. `isDirty()` continues to work (version comparison) but is now a derived field of the lifecycle model
5. No new services, no new stores, no new hooks — only extensions to existing WorkflowStore + WorkflowService
6. TypeScript passes with no new errors; existing tests pass

## Architecture

```
CommandDispatcher.execute()
    │
    ▼
DocumentStore.commit()  ← version++
    │
    ▼
WorkflowService.isDirty()  ← version > lastSavedVersion
    │
    ▼
WorkflowStore.getSnapshot()
    │
    ▼
{ revision, lastSavedRevision, isDirty, saveState, lastSavedAt, lastSaveReason, saveError }
```

## Non-goals

- ❌ No autosave scheduler (M3.3.2)
- ❌ No validation queue (M3.3.3)
- ❌ No publish pipeline (M3.3.4)
- ❌ No new service or store abstractions
- ❌ No UI components (status bar, toolbar badges — those are M3.3.2+ consumer work)

## Implementation

### WorkflowStore additions

- `_saveState: 'idle' | 'saving' | 'saved' | 'error'` (default: `'idle'`)
- `_saveError: string | null` (default: `null`)
- `_lastSaveReason: 'manual' | 'autosave' | null` (default: `null`)
- `_lastSavedAt: number` (default: `0`)
- `setSaveState(state, error?)` mutator
- `getSnapshot()` extended with `saveState`, `saveError`, `lastSaveReason`, `lastSavedAt`

### WorkflowService.save() changes

- Set `saveState = 'saving'` before persistence call
- On success: `saveState = 'saved'`, clear `saveError`
- On error: `saveState = 'error'`, capture `saveError`, re-throw
- `lastSaveReason` tracks the trigger (`'manual'` | `'autosave'`)
- `lastSavedAt` records timestamp

### Initial state on load

- After document loads and initializes, set `saveState = 'saved'` with `lastSavedAt = Date.now()`

## Invariants

1. **`isDirty` is always derived** — never stored independently. `isDirty = documentStore.version > workflowStore.lastSaveVersion`. No `setDirty()` mutator exists.
2. **`WorkflowStore` owns persistence lifecycle** — `saveState`, `saveError`, `lastSavedAt`, `lastSaveReason`, `lastSaveVersion`.
3. **`DocumentStore` owns document revision** — `version` is incremented by `commit()`, which only `CommandDispatcher` calls after successful command execution.
4. **`WorkflowService` is the only component** allowed to synchronize the two — calling `setLastSaveVersion(documentStore.version)` only within `WorkflowService.save()`.
5. **`saveState` is persistence-only** — publish state will be separate (`publishState`) when M3.3.4 arrives. Never overload `saveState` with publish or validation states.

## Design Decisions

- **No separate `DocumentStatus` type** — the fields are inlined into `WorkflowSnapshot`. A derived `DocumentStatus` interface is exported for consumer convenience.
- **`saveState` is persistence-only** — publish state will be separate (`publishState`) when M3.3.4 arrives.
- **`saveError` is `string | null`**, not `Error` — snapshots must be serializable. Full error objects belong in logs.
- **Re-throw on save error** — callers still need to handle the failure (e.g., show toast, retry). The state machine just captures it for downstream consumers (status bar, autosave scheduler).
