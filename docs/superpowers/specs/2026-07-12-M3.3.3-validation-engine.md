# M3.3.3 — Validation Engine & Problems Panel

## WHAT

Create a reactive validation pipeline that catches editing errors in real time and surfaces them through a Problems Panel. The system extends the existing `ValidationRegistry` and `ValidationEngine` infrastructure — wiring them into the event-driven architecture established in M3.3.

## Architecture

```
document.changed (eventBus)
       │
       ▼
ValidationService
       │
       ├── debounce (750ms default)
       ├── cancelPending() — supersedes older runs
       ├── queue if running — never interrupt mid-validate
       │
       ▼
ValidationEngine.validateAll(document)
       │
       ▼
ValidationRegistry
       │
       ├── Editor validators (cheap, realtime)
       │   ├── polygonClosureValidator
       │   ├── selfIntersectionValidator
       │   ├── duplicateIdsValidator
       │   ├── entranceConnectivityValidator
       │   ├── floorMetadataValidator
       │   ├── roadConnectivityValidator
       │   └── referenceValidator
       │
       ├── Publish validators (expensive, deferred)
       │   └── (empty in V1 — M3.3.4 fills this)
       ▼
ValidationIssue[]
       │
       ▼
ValidationStore.commit({ issues, revision, ... })
       │
       └── Consumers (read-only, through ValidationService)
           ├── ProblemsPanel
           ├── WorkflowService (isValid gate)
           ├── Publish (future)
           └── Toolbar/StatusBar (future)
```

Symmetry with AutosaveService:

```
document.changed
       │
       ├──► AutosaveService (5s debounce, persistence)
       └──► ValidationService (750ms debounce, correctness)
```

## Success Criteria

1. `ValidationService` extends `BaseEditorService`, registered in `createEditorContext()`
2. Reacts to `document.changed` with 750ms debounce, cancelable
3. Runs `validator.validate(document)` for each registered editor validator
4. Per-validator crash isolation — crashes become `ValidationIssue` items (never throw)
5. Results stored in `ValidationStore` with `lastValidatedRevision` matching `DocumentStore.version`
6. `runningRevision: number | null` exposed while validation is in flight
7. `ValidationService.isValid()` and `ValidationService.getSnapshot()` are the public API
8. ProblemsPanel bottom panel in StudioWorkspace, toggled by Ctrl+Shift+M
9. Clicking an issue row focuses the corresponding entity in the viewport (via SelectionManager, not CommandDispatcher)
10. 7 validators registered and producing issues at their documented scope
11. WorkflowService's save/publish read from `ValidationService` instead of calling their own validate
12. All existing tests pass; new tests cover validation lifecycle

## Invariants

- **ValidationService is the sole public API** — consumers never read ValidationStore directly. Services talk to services.
- **Viewport navigation is owned by ValidationService** — `focusIssue()` on ValidationService routes through SelectionManager/Viewport. Problems Panel never dispatches commands.
- **Validation never mutates the document** — it is read-only analysis of `CampusDocument`.
- **Validation never throws** — every validator crash is caught and stored as an issue.

- **Validators declare `cost: 'cheap' | 'expensive'`** — V1 runs only cheap validators in the reactive loop. Expensive validators are reserved for Publish (M3.3.4).
- **Validation runs are superseedable, not interruptible** — a running validation finishes; a newer revision queues one follow-up run.
- **`lastValidatedRevision` enables staleness detection** — any consumer can check if validation is current.

## Non-goals

- ❌ No expensive validators (overlapping rooms, routing compile)
- ❌ No publish-only validation yet (M3.3.4)
- ❌ No automatic fixes / quick-fix buttons
- ❌ No command palette integration
- ❌ No settings panel or user configuration
- ❌ No toolbar badges or status bar indicators (future enhancement)

## ValidationIssue Contract

```ts
interface ValidationLocation {
  type: 'polygon' | 'edge' | 'vertex' | 'point' | 'centroid'
  index?: number
}

interface ValidationIssue {
  id: string                        // `${validatorId}:${entityId ?? 'global'}:${hash(message)}`
  severity: 'error' | 'warning' | 'info'
  category: 'geometry' | 'duplicate' | 'connectivity' | 'metadata' | 'reference'     // 'publish' reserved for M3.3.4
  scope: 'campus' | 'building' | 'floor' | 'entity'
  entityId: string | null           // null = campus-level issue
  entityType: CampusEntityType | null
  message: string
  fixable: boolean                  // V1 always false — quick-fix deferred to future subsystem
  location?: ValidationLocation
  validatorId: string
}
```

## ValidatorPlugin Contract (extended)

```ts
interface ValidatorPlugin {
  id: string
  label: string
  scope: ValidationScope             // 'entity' | 'building' | 'campus'
  cost: 'cheap' | 'expensive'
  validate(document: CampusDocument): ValidationIssue[]
}
```

## Layers

### ValidationStore

New store. Follows the same pattern as `WorkflowStore` — snapshot-based, no business logic.

```ts
interface ValidationSummary {
  total: number
  errors: number
  warnings: number
  infos: number
}

interface ValidationStoreSnapshot {
  issues: ValidationIssue[]
  summary: ValidationSummary          // pre-computed counts
  lastValidatedRevision: number
  lastValidationTimestamp: number
  runningRevision: number | null     // non-null when validation is in flight
  isValid: boolean                   // summary.errors === 0
  pending: boolean                   // queued or running
}
```

Mutator: `commit(partial: Partial<ValidationStoreSnapshot>)` — atomic batch update.

### ValidationService

The reactive glue. Twin of `AutosaveService` in structure. **ValidationService is the sole public API** — consumers never read ValidationStore directly.

```
init():
  subscribe to eventBus 'document.changed'
  start debounce timer (no initial fire)

document.changed:
  if currently running:
    queue follow-up for latest revision
    return
  reset debounce

debounce fires:
  capture documentStore.version
  set runningRevision
  set pending
  await ValidationEngine.validateAll(document)
  store result with captured revision
  clear runningRevision, pending
  if follow-up queued, run immediately
```

Constructor options: `{ debounceMs?: number }` defaulting to 750ms.

Public API:
- `getSnapshot(): ValidationStoreSnapshot` — for UI consumers
- `isValid(): boolean` — reads snapshot.isValid
- `hasErrors(): boolean` — summary.errors > 0
- `validateNow(): Promise<void>` — force validation (for publish gate)
- `focusIssue(issue: ValidationIssue): void` — navigates viewport to issue's entity via SelectionManager/Viewport

ValidationService does NOT depend on WorkflowService. It depends on `eventBus`, `ValidationEngine` (wraps `ValidationRegistry`), `ValidationStore`, and `SelectionManager`/viewport infrastructure for `focusIssue()`.

### Validators (V1)

| Validator | Scope | Cost | Category | Checks |
|-----------|-------|------|----------|--------|
| `polygonClosureValidator` | entity | cheap | geometry | All polygon entities have ≥3 pts, first == last. Extended from buildings/rooms to all polygon types. |
| `selfIntersectionValidator` | entity | cheap | geometry | No self-intersecting edges. Currently dead code — register it. |
| `duplicateIdsValidator` | campus | cheap | duplicate | No duplicate entity IDs across entire document. Extended to all entity types (currently only buildings/floors/rooms). Also cross-type collisions (building ID must not collide with room ID). |
| `entranceConnectivityValidator` | entity | cheap | connectivity | Entrance references resolve: buildingId, floorId, roomId (if set) must exist. Entrance geometry belongs to referenced floor/building. |
| `floorMetadataValidator` | building | cheap | metadata | Floor has: valid id, name, level number, references existing building. Excludes descriptive metadata (description, thumbnail—those are publish concerns). |
| `roadConnectivityValidator` | entity | cheap | connectivity | Road endpoints connect to valid junctions/entities. Covers: endpoint validity, dangling roads. |
| `referenceValidator` | campus | cheap | reference | Every foreign key resolves: building→campus, floor→building, room→floor, road→floor, entrance→all referenced entities. Generic — not embedded in specialized validators. |

Interaction:
- **Click issue row** → `validation.focusIssue(issue)` → internally routes through SelectionManager/Viewport. Problems Panel does NOT dispatch commands or mutate the document.
- **Filter dropdown** → client-side filtering by `scope`, future: by `category`/`severity`
- **Empty state** → single green row: `✓ No problems detected`

Positioning: Resizable bottom panel in StudioWorkspace layout. Toggle: `Ctrl+Shift+M`.

### Edge cases

- **Empty document**: validation produces zero issues, `isValid === true`, `✓ No problems detected`
- **All validators crash**: each crash becomes a `ValidationIssue{severity: 'error', category: 'reference'}`, validation does not fail
- **Validation during rapid edits**: debounce resets, only one validation per ~750ms window; if currently running, queues one follow-up
- **Destroy during validation**: `ValidationService.destroy()` cancels pending runs, clears timers; in-flight validation resolves but store is not updated
- **Document destroyed/replaced**: revision counter resets; next `document.changed` runs fresh validation
- **Issue with no entityId**: campus-level issues (e.g., duplicate IDs across unrelated entities) render without focus capability
- **Null entityId**: Problems Panel shows the row but the click-to-focus is disabled
