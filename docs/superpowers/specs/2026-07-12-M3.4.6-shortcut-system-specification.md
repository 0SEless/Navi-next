# M3.4.6 — Shortcut & Command System Specification

**Status:** Accepted
**Date:** 2026-07-12
**Dependencies:** M3.4.1 (Editor Interaction), M3.4.5 (Input System), ADR 0015 (Service Boundaries)

---

## 1. Purpose

NAVI Studio currently handles keyboard input through ad-hoc `window.addEventListener('keydown', ...)` calls in `FloorEditorCanvas.tsx` and through tools that manually check `event.shiftKey`. There is no centralized shortcut system: keyboard-to-command mapping is scattered across components, there is no context hierarchy (tool shortcuts conflict with editor shortcuts), and there is no platform abstraction (Ctrl vs Cmd).

M3.4.6 defines the **Shortcut & Command System** — a service layer that extends the M3.4.5 input pipeline to handle keyboard events. It answers "what editor action does this key combination invoke?"

This is the second of two interaction architecture milestones:
- **M3.4.5 — Input System**: answers "what did the user physically do?"
- **M3.4.6 — Shortcut & Command System**: answers "what editor action does that interaction invoke?"

---

## 2. Shortcut Principles

1. **InputController is the sole owner of browser input listeners.** No other service attaches `keydown`, `keyup`, `pointer`, `wheel`, or `contextmenu` listeners directly to DOM elements, except where required by browser APIs (e.g., text inputs).
2. **ShortcutRegistry is stateless.** It resolves a `KeyboardInputFrame` + `ShortcutContext` into a `ResolvedShortcut`. It never stores session state or references to the active tool.
3. **ShortcutRegistry never executes commands.** It returns a declarative resolution. The caller dispatches.
4. **Platform abstraction is built-in.** Shortcuts are defined with `primary` (Ctrl on Win/Linux, Cmd on macOS), `secondary` (Shift), `alt` (Alt/Option), not with platform-specific keys.
5. **Context wins by priority.** Tool shortcuts beat editor shortcuts. Editor shortcuts beat global shortcuts. The resolution algorithm is deterministic.
6. **Reserved shortcuts are immutable.** `Ctrl+Z`, `Ctrl+S`, `Escape`, `Delete`, and five others can never be unregistered or overridden by non-reserved registrations.
7. **Shortcuts are declarative, not imperative.** A registration states "key X + modifiers Y → command Z." No registration contains logic.

## 3. Architecture

```
Browser keydown/keyup
        │
        ▼
┌───────────────────────────────────────────────────────┐
│                   InputController                      │
│  Receives keydown/keyup from the single DOM listener.  │
│  For modifier keys → ModifierTracker.update().         │
│  For non-modifier keys → build KeyboardInputFrame.    │
└───────────────────────┬───────────────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────────────┐
│                   InputRouter                          │
│  routeKeyboard(frame) — new routing path for keys.    │
│  Checks InputFocusManager.isKeyboardAllowed().        │
│  Forwards frame to ShortcutRegistry.resolve().        │
└───────────────────────┬───────────────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────────────┐
│                 InputFocusManager                      │
│  isKeyboardAllowed() gates keyboard routing:           │
│  - textInput → false (let the text field handle it)   │
│  - modal → false                                       │
│  - canvas → true                                       │
│  - explorer → partial (Enter/Space for rename, else)  │
└───────────────────────┬───────────────────────────────┘
                        │  if allowed
                        ▼
┌───────────────────────────────────────────────────────┐
│               ShortcutRegistry.resolve()               │
│  Receives KeyboardInputFrame + ShortcutContext.        │
│  Resolves against: Reserved → Tool → Editor → Global. │
│  Returns ResolvedShortcut.                           │
└───────────────────────┬───────────────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────────────┐
│              Interceptor Chain (seam)                  │
│  [interceptor, interceptor, ...]                       │
│  Each can: pass, block, redirect.                     │
│  Empty by default — reserved for future use.          │
└───────────────────────┬───────────────────────────────┘
                        │  if passed
                        ▼
┌───────────────────────────────────────────────────────┐
│                 CommandDispatcher                      │
│  dispatcher.execute(resolution.commandId, payload)     │
└───────────────────────────────────────────────────────┘
```

### Shared Pipeline (M3.4.5 + M3.4.6)

```
DOM
  │
  ▼
```

## 4. KeyboardInputFrame

Mirrors M3.4.5's `InputFrame` — an immutable snapshot of a single keyboard event.

```typescript
interface KeyboardInputFrame {
  /** The original browser event (for debugging). */
  readonly rawEvent: KeyboardEvent

  /** Normalized key string. Lowercase letters, readable symbols. */
  readonly key: string

  /** Browser event.code for positional keys (e.g. "KeyS", "Digit1"). */
  readonly code: string

  /** Modifier state at the moment this key was pressed. */
  readonly modifiers: ModifierState

  /** Whether this is a repeated keydown (held key). */
  readonly repeat: boolean

  /** Monotonic frame identifier (increments per event). */
  readonly frameId: number

  /** Timestamp of the original browser event. */
  readonly timestamp: DOMHighResTimeStamp

  /** Information about the currently focused DOM element. Facts, not decisions. */
  readonly target: {
    tagName: string
    isContentEditable: boolean
  }
}
```

**Key normalization:**

| Browser `event.key` | Normalized `key` |
|---|---|
| `"s"` | `"s"` |
| `"S"` | `"s"` (Shift is captured in modifiers) |
| `"1"` | `"1"` |
| `"Escape"` | `"escape"` |
| `"Delete"` | `"delete"` |
| `"Backspace"` | `"backspace"` |
| `"Enter"` | `"enter"` |
| `" "` | `"space"` |
| `"?"` | `"?"` |

The `target` field contains facts about what element is focused. The `InputFocusManager` derives focus context from these facts. The frame itself does not interpret them — that separation keeps the frame a value type.

## 5. ShortcutContext

The active context at resolution time. Passed explicitly to `ShortcutRegistry.resolve()` to keep the registry stateless.

```typescript
interface ShortcutContext {
  /** The currently active tool ID, or undefined if no tool context. */
  activeToolId?: string

  /** The current editing mode. */
  editorMode: EditorMode

  /** Focus context from InputFocusManager. */
  focus: FocusContext
}
```

This context is assembled by the `InputRouter` (or the caller of `resolve()`) from:
- `ToolRegistry.activeToolId`
- `EditingContextService.mode`
- `InputFocusManager.current`

## 6. ShortcutRegistry

The primary service for shortcut registration and resolution.

### Registration

```typescript
interface ShortcutRegistration {
  /** Human-readable identifier (auto-generated if not provided). */
  id?: string

  /** Normalized key to match. */
  key: string

  /** Required modifier state. Omitted modifiers are wildcard (any state). */
  modifiers?: {
    primary?: boolean    // Ctrl (Win/Linux) or Cmd (macOS)
    secondary?: boolean  // Shift
    alt?: boolean        // Alt (Win/Linux) or Option (macOS)
  }

  /** Command to execute. */
  commandId: string

  /** Optional payload to pass with the command. */
  payload?: Record<string, unknown>

  /** Context scope. */
  context: 'tool' | 'editor' | 'global'

  /** Required when context === 'tool'. */
  toolId?: string

  /** Display metadata. */
  label: string
  group: string
  description?: string

  /** Whether this shortcut fires on key repeat (default: false). */
  allowRepeat?: boolean
}

class ShortcutRegistry extends BaseEditorService {
  readonly id = 'shortcutRegistry'
  readonly dependencies: readonly string[] = ['eventBus']

  /** Register a shortcut. Returns the registration ID. */
  register(shortcut: ShortcutRegistration): string

  /** Unregister by registration ID. */
  unregister(id: string): void

  /** Register a provider. Its registerShortcuts() is called immediately. */
  registerProvider(provider: ShortcutProvider): void

  /** Resolve a keyboard frame against all registered shortcuts. */
  resolve(frame: KeyboardInputFrame, context: ShortcutContext): ResolvedShortcut
}
```

### ShortcutProvider

Features own their shortcuts instead of a centralized registration file.

```typescript
interface ShortcutProvider {
  readonly providerId: string
  registerShortcuts(registry: ShortcutRegistry): void
}
```

Tool classes implement both `Tool` and `ShortcutProvider`:

```typescript
class DrawRoadTool implements Tool, ShortcutProvider {
  readonly providerId = 'tool.drawRoad'

  registerShortcuts(registry: ShortcutRegistry): void {
    registry.register({
      key: 'escape',
      commandId: 'drawing.cancel',
      context: 'tool',
      toolId: 'draw-road',
      label: 'Cancel Drawing',
      group: 'Drawing',
    })
  }
}
```

`registerProvider()` calls `provider.registerShortcuts(this)` immediately. Removing a provider requires tracking its registration IDs — see Section 6.

### Resolution

```typescript
interface ResolvedShortcut {
  /** True if a matching shortcut was found and not blocked. */
  handled: boolean

  /** The matching command ID (if handled). */
  commandId?: string

  /** The payload to pass with the command (if any). */
  payload?: Record<string, unknown>

  /** The registration that matched (for introspection/tooltips, help overlay, command palette). */
  shortcut?: ShortcutRegistration

  /** Which context priority matched (tool > editor > global). */
  context?: 'tool' | 'editor' | 'global'

  /** Reason for not handling (for debugging). */
  reason?: 'noMatch' | 'focusBlocked' | 'repeatIgnored' | 'intercepted'
}
```

### Resolution Algorithm

`ShortcutRegistry.resolve()` iterates its own registrations by context priority. Reserved shortcuts are handled by `ReservedShortcutRegistry.resolve()` before this is called (see Section 10).

```
resolve(frame, context):

  1. If frame.target is an input/textarea/contentEditable
     → return { handled: false, reason: 'focusBlocked' }
     (This is a safety net — InputFocusManager should have already gated,
      but the registry enforces it too.)

  2. For each context priority: tool → editor → global

     For each registration in the current context:
       a. If the key doesn't match → skip
       b. If modifiers don't match → skip
          (omitted modifier = wildcard, present modifier = must match)
       c. If context === 'tool' and toolId !== context.activeToolId → skip
       d. If !allowRepeat and frame.repeat === true → skip
       e. Match found → return {
            handled: true,
            commandId,
            payload,
            shortcut: registration,
            context: currentContext,
          }

  3. No match found → return { handled: false, reason: 'noMatch' }
```

### Registration ID

Each call to `register()` returns a unique string ID. This is used for `unregister()`:

```typescript
const id = registry.register({ ... })
registry.unregister(id)
```

This avoids the ambiguity of `unregister(commandId)` where multiple shortcuts might map to the same command (e.g., Delete and Backspace both mapping to `entity.delete`).

## 7. ReservedShortcutRegistry

A read-only, immutable registry that contains shortcuts that must never be overridden or unregistered.

```typescript
class ReservedShortcutRegistry extends BaseEditorService {
  readonly id = 'reservedShortcutRegistry'
  readonly dependencies: readonly string[] = ['eventBus']

  /** Get all reserved shortcuts (read-only). */
  getAll(): ReadonlyArray<ShortcutRegistration>

  /** Check if a command is reserved. */
  isReserved(commandId: string): boolean

  /**
   * Resolve a keyboard frame against reserved shortcuts.
   * Includes special handling for Escape (Cancel Priority — see Section 12).
   * Called by routeKeyboard() before ShortcutRegistry.resolve().
   */
  resolve(frame: KeyboardInputFrame, context: ShortcutContext): ResolvedShortcut
}
```

### Built-in Reserved Shortcuts

| Shortcut | Command ID | Context | Notes |
|---|---|---|---|
| `Primary+Z` | `history.undo` | Global | |
| `Primary+Shift+Z` | `history.redo` | Global | |
| `Primary+S` | `workflow.save` | Global | |
| `Primary+A` | `selection.selectAll` | Editor | |
| `Delete`, `Backspace` | `entity.delete` | Editor | Both keys map to the same command |
| `Escape` | — | Global | Dispatched dynamically (see Cancel Priority below) |
| `Primary+C` | `entity.copy` | Editor | |
| `Primary+V` | `entity.paste` | Editor | |
| `Primary+D` | `entity.duplicate` | Editor | |

These are matched **before** any other registry. If a reserved shortcut matches, resolution stops and the command is returned. No tool or plugin registration can intercept these.

### Escape Handling

`Escape` is reserved but its behavior depends on context:

```
1. Drawing active (PreviewManager.isActive)
   → dispatch drawing.cancel

2. Tool active with custom Escape handler
   → dispatch tool's Escape command

3. Selection exists
   → dispatch selection.clear

4. Nothing to cancel
   → return { handled: false }
```

This is handled by a special resolution path within `ReservedShortcutRegistry` rather than a single registration.

## 8. Platform Abstraction

Shortcuts are defined with platform-agnostic modifier names. The resolution layer maps them to the correct physical keys based on the user's platform.

```typescript
// Registration — never references "ctrl" or "meta" directly
registry.register({
  key: 's',
  modifiers: { primary: true },
  commandId: 'workflow.save',
  context: 'global',
  label: 'Save Document',
  group: 'Workflow',
})

// Resolution mapping
primary  → Ctrl on Windows/Linux, Cmd on macOS
secondary → Shift on all platforms
alt      → Alt on Windows/Linux, Option on macOS
```

The `ModifierState` from `KeyboardInputFrame` uses the physical keys (`modifiers.ctrl`, `modifiers.meta`, `modifiers.shift`, `modifiers.alt`). The registry's resolution algorithm translates:

```
isPrimaryHeld = (platform === 'mac' ? modifiers.meta : modifiers.ctrl)
isAltHeld    = (platform === 'mac' ? modifiers.alt  : modifiers.alt)
```

The platform is detected once at startup and cached. The `ShortcutRegistry` stores the platform as an internal constant.

## 10. InputRouter Changes

A new `routeKeyboard()` method is added to the `InputRouter` defined in M3.4.5.

```typescript
class InputRouter extends BaseEditorService {
  // Existing methods (from M3.4.5):
  routeGesture(event: GestureEvent, ctx: ToolContext): ToolResult
  routeRawPointer(event: NormalizedPointerEvent, ctx: ToolContext): ToolResult
  routeWheel(event: WheelEventData, ctx: ToolContext): ToolResult

  // New method:
  routeKeyboard(frame: KeyboardInputFrame): ResolvedShortcut {
    // 1. Check InputFocusManager.isKeyboardAllowed()
    //    → if false, return { handled: false, reason: 'focusBlocked' }
    //
    // 2. Build ShortcutContext from ToolRegistry + EditingContext + InputFocusManager
    //
    // 3. Call ReservedShortcutRegistry.resolve(frame, context)
    //    → if handled, return it (reserved shortcuts bypass interceptors)
    //
    // 4. Call ShortcutRegistry.resolve(frame, context)
    //    → if handled:
    //        a. Run interceptor chain
    //        b. If intercepted → return { handled: false, reason: 'intercepted' }
    //        c. If passed → return resolution
    //
    // 5. Return { handled: false, reason: 'noMatch' }
  }
}
```

## 11. Interceptor Chain (Seam)

A pre-dispatch hook that can block or redirect resolved shortcuts. Empty by default — reserved for future use.

```typescript
interface ShortcutInterceptor {
  /** Unique ID for this interceptor. */
  id: string

  /** Priority (higher runs first). Default: 0. */
  priority?: number

  /**
   * Called before dispatch. Return:
   * - 'pass' → continue to dispatch
   * - 'block' → abort dispatch (resolution.reason = 'intercepted')
   * - 'redirect' → dispatch a different command instead
   */
  intercept(
    frame: KeyboardInputFrame,
    resolution: ResolvedShortcut
  ): InterceptorResult
}

type InterceptorResult =
  | { action: 'pass' }
  | { action: 'block'; reason?: string }
  | { action: 'redirect'; commandId: string; payload?: Record<string, unknown> }

class ShortcutRegistry extends BaseEditorService {
  /** Register an interceptor. */
  addInterceptor(interceptor: ShortcutInterceptor): void

  /** Remove an interceptor. */
  removeInterceptor(id: string): void
}
```

The interceptor chain runs only for shortcuts resolved by `ShortcutRegistry` (non-reserved). Reserved shortcuts bypass interceptors — they are immutable.

**Use cases (future):**

| Interceptor | Purpose |
|---|---|
| Workflow guard | Block `entity.delete` when document is read-only |
| Busy guard | Block shortcuts while a publish is in progress |
| Accessibility | Redirect certain shortcuts for accessibility modes |

No interceptors are registered by default in M3.4.6. The chain is a seam for future extension.

## 12. Cancel Priority

`Escape` is the most complex shortcut because its behavior depends on editor state. The resolution follows the M3.4.1 Cancel Priority:

```
1. Preview active → dispatch drawing.cancel
   (PreviewManager.isActive === true)

2. Tool active with registered Escape handler → dispatch tool command

3. Selection exists → dispatch selection.clear

4. Nothing → return { handled: false }
```

This is implemented as a special resolution path within `ReservedShortcutRegistry` since Escape is reserved and immutable.

|---|---|---|---|---|

| `Primary+S` | `workflow.save` | Global | Reserved | No |
| `Primary+A` | `selection.selectAll` | Editor | Reserved | No |

| `Escape` | (dynamic) | Global | Reserved | No |
| `Enter` | (Confirm Panel confirm) | Tool | Tool | No |
| `Primary+C` | `entity.copy` | Editor | Reserved | No |
| `Primary+V` | `entity.paste` | Editor | Reserved | No |
| `Primary+D` | `entity.duplicate` | Editor | Reserved | No |
| `1`–`9` | `tool.activate(N)` | Global | Editor | No |
| `Primary+F` | `explorer.search` | Editor | Editor | No |
| `?` | `shortcuts.showHelp` | Global | Editor | No |

**Tool-defined shortcuts** (registered per tool):

| Tool | Shortcut | Command ID |
|---|---|---|
| Select | `Escape` | `selection.clear` |
| Draw Building | `Escape` | `drawing.cancel` |
| Draw Road | `Escape` | `drawing.cancel` |
| Draw Room | `Escape` | `drawing.cancel` |

When a drawing tool is active, its `Escape` registration (context: tool, toolId: 'draw-road') matches before the reserved `Escape`, because the tool context is checked between reserved and editor registrations. Actually — Escape is reserved, so it would match in the ReservedRegistry first. The resolution algorithm needs to handle this: reserved `Escape` dynamically delegates to the tool if Preview is active.

Let me clarify: `ReservedShortcutRegistry` handles `Escape` specially — it checks PreviewManager and tool context internally before returning a resolution. If a tool has registered its own Escape handler AND Preview is active, Preview wins (that's the Cancel priority). If Preview is not active, the tool's handler wins.

## 15. Event Flow Examples

### Ctrl+S Save Document

```
User presses Ctrl+S

Browser → keydown (key: 'Control', code: 'ControlLeft')
    │
InputController:
    └─ ModifierTracker.processKeyDown(event) → { ctrl: true }
        └─ Emits modifiersChanged { ctrl: true }

Browser → keydown (key: 's', code: 'KeyS')
    │
InputController:
    ├─ ModifierTracker already has ctrl=true
    ├─ Build KeyboardInputFrame:
    │     key: 's', modifiers: { ctrl: true, ... }
    │     repeat: false, frameId: 87
    │     target: { tagName: 'CANVAS', isContentEditable: false }
    └─ Forward to InputRouter.routeKeyboard(frame)

InputRouter:
    ├─ InputFocusManager.isKeyboardAllowed() → true (canvas is focused)
    ├─ Build ShortcutContext:
    │     activeToolId: 'select'
    │     editorMode: 'campus'
    │     focus: 'canvas'
    └─ ReservedShortcutRegistry.resolve(frame, context):
        ├─ 'primary' → ctrl on this platform → match ✓
        ├─ key 's' → match ✓
        ├─ no modifiers/secondary/alt → match ✓
        └─ return { handled: true, commandId: 'workflow.save' }
    └─ Interceptor chain → empty → pass

InputRouter:
    └─ dispatcher.execute({ id: 'workflow.save' })
```

### Escape During Drawing

```
User is drawing a road, presses Escape

Browser → keydown (key: 'Escape', code: 'Escape')
    │
InputController:
    ├─ ModifierTracker: Escape is not a modifier, no change
    ├─ Build KeyboardInputFrame: key: 'escape'
    └─ Forward to InputRouter.routeKeyboard(frame)

InputRouter:
    ├─ Build ShortcutContext:
    │     activeToolId: 'draw-road'
    │     editorMode: 'floor'
    │     focus: 'canvas'
    │
    ├─ ReservedShortcutRegistry.resolve(frame, context):
    │     ├─ key 'escape' → match
    │     ├─ Preview active? Yes → dispatch drawing.cancel
    │     └─ return { handled: true, commandId: 'drawing.cancel' }
    │
    └─ dispatcher.execute({ id: 'drawing.cancel' })
```

### Delete Key While Text Input is Focused

```
User is typing a room name, presses Delete

Browser → keydown (key: 'Delete', code: 'Delete')
    │
InputController:
    ├─ Build KeyboardInputFrame:
    │     key: 'delete'
    │     target: { tagName: 'INPUT', isContentEditable: false }
    └─ Forward to InputRouter.routeKeyboard(frame)

InputRouter:
    ├─ InputFocusManager.isKeyboardAllowed() → false (textInput context)
    └─ return { handled: false, reason: 'focusBlocked' }
        The Delete key is NOT forwarded. The text field handles it natively.
```

### Tool-Specific Shortcut (Escape While Drawing)

```
Tool 'draw-road' registered {
    key: 'escape',
    commandId: 'drawing.cancel',
    context: 'tool',
    toolId: 'draw-road',
}

User presses Escape while draw-road is active (no Preview)

Browser → keydown (key: 'Escape')
    │
InputRouter:
    ├─ ReservedShortcutRegistry:
    │     Escape matched but no Preview active, no selection → fall through
    │     (Reserved Escape returns { handled: false } when nothing to cancel)
    │
    └─ ShortcutRegistry.resolve(frame, context):
        ├─ Tool registry iteration:
        │   key: 'escape' → match
        │   modifiers: none → match
        │   context === 'tool', toolId === 'draw-road' → match
        │   → return { handled: true, commandId: 'drawing.cancel' }
        │
        └─ dispatcher.execute({ id: 'drawing.cancel' })
```

## 16. Non-Goals

The following are intentionally excluded from M3.4.6:

- User-configurable keymap UI → post-M3.4
- Command palette implementation → post-M3.4 (reserved `Ctrl+Shift+P`)
- Multi-key chords (Ctrl+K, Ctrl+S like VS Code) → post-M3.4
- Gamepad or accessibility device input → future milestone
- Macro recording or playback → future milestone
- Input visualization (showing pressed keys on screen) → post-M3.4
- Hardware keyboard layout detection (AZERTY vs QWERTY) → post-M3.4

## 18. Implementation Boundaries

This document specifies **shortcut system architecture only**. It intentionally does not prescribe:

- React components or hooks for the `?` help overlay
- CSS, styling, or layout for shortcut visualization
- Persistence format for user-configured keymaps (future)

Those belong to implementation plans (M3.4.6B).

## 19. Shortcut System Invariants

1. **No service other than InputController attaches keyboard listeners to the DOM.**
2. **ShortcutRegistry is stateless.** It resolves a frame + context to a resolution. It stores no session state.
3. **Reserved shortcuts can never be unregistered.** They are immutable for the lifetime of the editor.
4. **All shortcut registrations use platform-agnostic modifiers.** No registration references `ctrl` or `meta` directly.
5. **Registration ID is the only way to unregister.** Unregistering by command ID is not supported.
6. **The interceptor chain is empty by default.** It is a seam, not a feature.
7. **ShortcutRegistry never executes commands.** It returns a `ResolvedShortcut`. The caller dispatches.
8. **Resolution is deterministic.** For the same frame + context, the same `ResolvedShortcut` is always returned.
9. **Cancellation (Escape) follows a fixed priority:** Preview > Tool > Selection > Nothing.

## 20. Completion Criteria

M3.4.6 is complete when:

 1. `ShortcutRegistry` is implemented with `register()`, `unregister()`, `registerProvider()`, and `resolve()`.
 2. `ShortcutProvider` interface exists; tools and modules register shortcuts via `registerProvider()` rather than direct `register()` calls.
 3. `ReservedShortcutRegistry` contains all immutable shortcuts from the reserved table.
 4. `InputController` forwards non-modifier keyboard events to `InputRouter.routeKeyboard()`.
 5. `InputRouter.routeKeyboard()` checks `InputFocusManager.isKeyboardAllowed()` before resolving.
 6. Resolution follows the formal algorithm: Reserved → Tool → Editor → Global → No Match.
 7. Platform-agnostic modifiers (`primary`, `secondary`) are correctly mapped at resolution time.
 8. All shortcuts from the M3.4.1 reserved table are either registered or explicitly reserved.
 9. Tool-specific shortcuts can be registered and are resolved in the tool context layer.
 10. Escape follows the Cancel Priority (Preview → Tool → Selection → Nothing).
 11. Keyboard input while a text field is focused is correctly gated by `InputFocusManager`.
 12. The `?` shortcut help overlay is driven by `ShortcutRegistry.getCatalog()`.
 13. No existing `window.addEventListener('keydown', ...)` calls remain in the editor codebase.
