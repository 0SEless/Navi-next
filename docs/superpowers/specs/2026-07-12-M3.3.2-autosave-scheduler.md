# M3.3.2 — Autosave Service

## WHAT

Create an `AutosaveSchedulerService` that owns the timing of autosaves — decides **when** to call `WorkflowService.save('autosave')`, never **how** to save.

## Architecture

```
document.changed (eventBus)
    │
    ▼
AutosaveService
    │
    ├─ debounce timer (configurable, default 5s)
    ├─ max interval timer (configurable, default 30s)
    ├─ internal pending flag (prevents concurrent saves)
    ├─ guard: workflow.canAutosave()
    │            ├── isDirty()
    │            └── saveState === 'idle'
    │
    ▼
WorkflowService.save('autosave')
    │
    ▼
PersistenceService
```

## Success Criteria

1. `AutosaveService` extends `BaseEditorService` with `id = 'autosave'`
2. Subscribes to `eventBus` `document.changed` event to reset debounce timer
3. Uses constructor options: `{ debounceMs: number, maxIntervalMs: number }` with sensible defaults
4. On debounce fire: checks `workflow.canAutosave()` — which checks `isDirty()` AND `saveState === 'idle'`
5. Max interval timer fires regardless of activity, with same guards
6. Internal `pending` flag prevents concurrent saves — even if debounce and interval fire simultaneously
7. `workflow.save('autosave')` promise rejections are caught (no unhandled rejections)
8. No UI awareness — no status bar, no toolbar, no settings panel
9. Registered in `createEditorContext()` like other services
10. `destroy()` clears both timers and unsubscribes; `init()` starts max interval and event subscription
11. `WorkflowService.canAutosave()` added as the single checkpoint that the scheduler calls — keeps `WorkflowStore` as an implementation detail
12. TypeScript passes with no new errors; existing tests pass

## Invariants

- **AutosaveScheduler never decides *how* to save. It only decides *when* to call `WorkflowService.save('autosave')`.**
- **The scheduler must never initiate concurrent saves.** The `saveState === 'idle'` guard ensures only one save is in flight at a time — rapid edits queue at most one autosave after the current save completes.
- **The subscribed event (`document.changed`) always represents a committed document change** — `CommandDispatcher` emits it only after `DocumentStore.commit()` succeeds. Autosave reacts to committed changes, not speculative mutations.
- No direct calls to `PersistenceService.save()` — always through `WorkflowService`.
- No subscription to `DocumentStore` directly — always through `eventBus.document.changed`.
- Timer values are constructor-configurable (for testing), never user-configurable (YAGNI).

## Non-goals

- ❌ No user-facing settings panel
- ❌ No status bar indicator
- ❌ No "disable autosave" toggle
- ❌ No validation integration (M3.3.3)
- ❌ No UI components of any kind

### WorkflowService addition

```ts
canAutosave(): boolean {
  if (!this.documentStore) return false
  return this.isDirty() && this.workflowStore.getSnapshot().saveState === 'idle'
}
```

### AutosaveService concurrency guard

```ts
private tryAutosave(): void {
  if (this.pending) return
  if (!this.workflow?.canAutosave()) return

  this.pending = true
  void this.workflow.save('autosave').catch(() => {
    // WorkflowStore already records error state. Nothing to do.
  }).finally(() => {
    this.pending = false
  })
}
```
